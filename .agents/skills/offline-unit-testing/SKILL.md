# Offline Unit Testing Skill

This skill defines testing practices and mock architectures to validate embedded modules on the host without requiring physical nRF52833 hardware.

## Core Testing Strategies

### 1. Mocking Hardware Peripherals
Since hardware cannot be physically connected in host tests, create lightweight mock drivers:
- **I2C / SPI Mocks:** Provide fixed byte arrays mimicking sensor registers (e.g. BMP390 calibration registers, chip ID register `0x00 = 0x60`).
- **UART Mocks:** Inject simulated UBX binary frames (`UBX-NAV-PVT`) or NMEA sentences into the parser buffer to test sentence recognition and state transitions.

```cpp
// Example: Mock I2C transaction table
struct MockI2CTransaction {
    uint8_t reg;
    uint8_t data[16];
    size_t length;
};
```

### 2. Fixed-Point Arithmetic & Edge-Case Validation
For algorithms in `middleware/` (e.g. `vario_engine.cpp`, `gnss_processor.cpp`, `battery_monitor.cpp`):
- **Range & Overflow Testing:** Test extreme pressure inputs (e.g. 30000 Pa to 110000 Pa) and verify that 32-bit and 64-bit math does not overflow or underflow.
- **Filter Step Response:** Feed constant delta-pressure inputs into the IIR filter and verify convergence to expected steady-state climb rate.
- **Battery SoC LUT:** Verify piecewise linear interpolation across the entire range (3.0V to 4.2V), especially edge values.

### 3. Circular Buffers & Ring Buffer Wraparound
- Test ring buffers at capacity ($N - 1$, $N$, $N + 1$ elements).
- Verify read/write index wraparounds when pointers exceed the buffer length.
- Confirm zero heap allocation throughout the test suite.

### 4. NMEA / LK8EX1 Sentence Formatting & Checksum Verification
- Verify that `LK8EX1` sentences generated by `lk8ex1_formatter.cpp` match standard NMEA format:
  `$LK8EX1,99540,154,12,23,4100*41\r\n`
- Validate that the computed XOR checksum strictly matches standard NMEA-0183 specifications.
